# Solar Dashboard API server

A small read-only REST API for the Solar Dashboard exercise, written with
built-in Node.js modules only (no dependencies). All data is loaded into
memory at startup, and requests are handled asynchronously, so the server
supports any number of concurrent requests.

## Run

From the exercise folder:

```bash
npm run server
```

or directly:

```bash
node server/index.cjs
```

The server listens on `http://localhost:3000` with CORS enabled. Every
response has a small artificial delay (300-800 ms) so loading states are
visible in the app.

## Endpoints

| Method | Path | Returns |
| --- | --- | --- |
| GET | `/companies` | All companies |
| GET | `/sites?companyId=<id>` | The sites of one company |
| GET | `/activities?siteId=<id>&period=<kind>` | Daily activities of one site, filtered by period |
| GET | `/washes?siteId=<id>&period=<kind>` | Washes of one site, filtered by period |
| GET | `/<collection>/<id>` | One record by its UUID |

Any query parameter other than `period` is a plain equality filter on the
record fields. The `period` parameter is supported only on `/activities` and
`/washes`:

| `period` value | Days returned |
| --- | --- |
| (omitted) | All days |
| `this-quarter` | The last 3 months, up to today |
| `last-year-quarter` | The same 3 months, one year earlier |
| `this-month` | The last month, up to today |
| `last-year-month` | The same month, one year earlier |

An unknown period value or resource returns a JSON error with status 400/404.

## Data

The data lives in [data](./data), one JSON file per collection:
`companies.json` (4), `sites.json` (30), `activities.json` (one record per
site per day, 2024-01-01 to 2026-12-31), and `washes.json`.

The data is generated by [generate-data.cjs](./generate-data.cjs) and is
intentionally realistic:

- Sunlight hours follow the seasons (about 4-5 hours in winter, 10-12 in
  summer), with more cloudy days in winter.
- Each site has its own clean-panel capacity (kWh per sunlight hour).
- Panels get dirty: efficiency is stable for ~2 weeks after a wash, then
  decays. After months with no wash, production drops close to zero. A wash
  restores full efficiency.
- Wash gaps are usually 4-8 weeks, but some sites have neglect periods of
  4-6 months.

To regenerate the data (new ids, same overall shape):

```bash
npm run generate-data
```

Restart the server after regenerating.
